# Pre-Release Audit — 2026-05-29

Point-in-time, code-inspected audit of the whole monorepo (`apps/web`, `apps/api`,
`packages/shared-types`, `supabase/migrations`, CI/tooling). Covers correctness *and*
organization/navigability. See [IMPLEMENTATION_STATUS.md](../IMPLEMENTATION_STATUS.md) for the status
legend; planning intent belongs in [KANBAN_BOARD.md](../KANBAN_BOARD.md).

**Method.** Three read-only sweeps returned a near-spotless "clear for release"; every load-bearing claim
was then re-verified by hand (migration redefinition chains, a live `plpgsql_check`/`pg_proc` pass against
the running local DB, the API client boundary, CI config). Several sweep conclusions were wrong — corrected
below.

## Verdict

Genuinely disciplined codebase: strict TS everywhere, RLS on every table, zero `console.log`/`TODO` in
source, complete auth + rate-limit coverage, idempotency/If-Match wired, schema↔AI-generator sync intact,
dev-code prod-stripping correct. **No confirmed Sev-1 in `main`.** The real exposure was a *class* of bug
(dropped-column RPC drift) that nothing automated guarded — now closed (H1).

## H1 — what shipped

`supabase db lint` (wraps `plpgsql_check`) validates every `public` function **body** against the live
schema and fails on any error-level finding (e.g. `column "x" does not exist`). This is the half the
existing **schema-drift sentinel** can't cover — that sentinel diffs generated *types* (signatures + table
shapes), and a function whose body selects a dropped column is late-bound: `CREATE OR REPLACE` accepts it
and the generated types don't change, so it sails past the diff.

- `package.json` → `db:lint` script (`supabase db lint --level error --fail-on error --schema public`).
- `.github/workflows/integration.yml` → "Function-body schema lint" step, right after the drift sentinel,
  reusing the already-booted stack.
- Verified: clean schema → exit 0 (4 pre-existing benign `42804` `bulk_*` warnings stay below the error
  gate); an injected `SELECT card_type` → `error / 42703` (proven in a rolled-back txn). `supabase db lint`
  creates/drops `plpgsql_check` transiently, so it does **not** pollute `public` or leak into `db:types`.
