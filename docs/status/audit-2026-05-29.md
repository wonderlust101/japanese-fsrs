## H1 — what shipped

`supabase db lint` (wraps `plpgsql_check`) validates every `public` function **body** against the live
schema and fails on any error-level finding (e.g. `column "x" does not exist`). This is the half the
existing **schema-drift sentinel** can't cover — that sentinel diffs generated *types* (signatures + table
shapes), and a function whose body selects a dropped column is late-bound: `CREATE OR REPLACE` accepts it
and the generated types don't change, so it sails past the diff.

- `package.json` → `db:lint` script (`supabase db lint --level error --fail-on error --schema public`).
- `.github/workflows/integration.yml` → "Function-body schema lint" step, right after the drift sentinel,
  reusing the already-booted stack.
- Verified: clean schema → exit 0 (4 pre-existing benign `42804` `bulk_*` warnings stay below the error
  gate); an injected `SELECT card_type` → `error / 42703` (proven in a rolled-back txn). `supabase db lint`
  creates/drops `plpgsql_check` transiently, so it does **not** pollute `public` or leak into `db:types`.
